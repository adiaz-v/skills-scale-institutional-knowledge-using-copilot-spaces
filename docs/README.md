# OctoAcme Project Management Docs

## Overview
Welcome to the OctoAcme Project Management documentation. These documents capture the core processes, roles, workflows, artifacts, and rhythms we use to plan, deliver, and continuously improve projects at OctoAcme. This README serves as a single entry point to orient new contributors and provide quick links to the detailed process documents.

All project contributors should use these docs for onboarding, planning, execution, and retrospection. The guidance emphasizes clear ownership, iterative delivery, risk and quality management, and open communication.

## Summary of Project Management Processes
- Lifecycle: Initiation → Planning → Execution → Release → Retrospective
- Roles: Project Manager, Product Manager, Developers, QA, Stakeholders
- Artifacts: One-pagers, project plans, backlogs, risk registers, release notes
- Rhythms: Daily standups, planning sessions, sprint/iteration reviews, retrospectives, stakeholder updates
- Key emphases:
  - Clear ownership and decision rights
  - Iterative delivery and frequent feedback
  - Risk identification and mitigation
  - Quality gates and release readiness checks
  - Transparent communication and documentation

## How to use these docs
1. New projects: start with the Project Initiation Guide to create the one-pager and align stakeholders.
2. During planning: use the Project Planning doc to create milestones, success criteria, and a backlog.
3. During execution: follow Execution & Tracking for standups, metrics, and cadence.
4. Before releases: follow the Release & Deployment Guide and confirm readiness with stakeholders.
5. After completion: run a Retrospective, capture actions, and update process docs if needed.
